A layered approach to agent security.

Agents connect model reasoning with data and tools. That makes their boundaries an architectural concern.

Start with the workflow

An enterprise agent may read internal information, call a cloud-hosted model, and execute tools. Each step crosses a boundary. A security design needs to account for the full sequence, including what enters the system, what tools can do, and what leaves it.

Five complementary controls

  1. Input guardrails. Inspect incoming requests before they influence the workflow.
  2. Role-based tool access. Limit the actions an agent can perform to those needed for its role.
  3. Output data-loss prevention. Check generated responses before information leaves the system.
  4. End-to-end auditability. Make relevant actions and decisions traceable.
  5. Human oversight. Include review where autonomous actions require additional judgment.

Treat the layers as a system

No individual control resolves every risk. Their value comes from how they work together across the workflow. The paper also discusses a hybrid cloud and on-premises architecture for regulated workloads.
